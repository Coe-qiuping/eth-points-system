## 三、接口契约（并行开发的前提）

> 没有这一节，C 和 D 只能干等 B 部署。**第 0 天必须定下来。**

### 3.1 地址来源

`scripts/deploy.js` 生成 `deployments.json`：

```json
{
  "chainId": "31337",
  "token": "0x5FbDB2315678afecb367f032d93F642f64180aa3",
  "store": "0xe7f1725E7734CE288F8367e1Bb143E90bb3F0512",
  "owner": "0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266",
  "users": ["0x70997970..."],
  "deployedAt": "2026-11-18T..."
}
```

A 把它转成 `frontend/src/contracts.json`（含地址 + 精简 ABI），前端只读这个文件。

### 3.2 数据结构

```js
// 余额：bigint，decimals = 0
await token.balanceOf(address)              // → 1000n
formatUnits(balance, 0)                     // → "1000"

// 商品 Product
{ id: bigint, name: string, description: string, price: bigint, stock: bigint, active: boolean }
await store.getProducts()                   // → Product[]

// 兑换记录 Redemption
{ productId: bigint, productName: string, price: bigint, timestamp: bigint, blockNumber: bigint }
await store.getUserRedemptions(address)     // → Redemption[]

// 全局指标
await token.totalIssued()                   // 累计发行
await token.totalConsumed()                 // 累计销毁
await token.circulatingSupply()             // 流通量 = 发行 - 销毁
await store.totalSpent(address)             // 该用户累计消费
```

### 3.3 历史条目统一格式（C 与 D 共用）

```js
{
  type: 'issue' | 'transferIn' | 'transferOut' | 'consume' | 'redeem',
  amount: number,            // 绝对值，不带正负号
  counterparty: string | null, // 对手方地址；发行/消耗为 null
  txHash: string,
  blockNumber: number,
  time: string,              // 本地时间字符串
  note: string               // 商品名 / 备注，可能为空
}
```

判定规则（D 实现时照此写）：

| 事件 | 判定条件 | type |
|---|---|---|
| `Transfer(0x0 → me)` | `from === ZeroAddress` | `issue` |
| `Transfer(me → 0x0)` | `to === ZeroAddress` | `consume` |
| `Transfer(me → x)` | 其他 | `transferOut` |
| `Transfer(x → me)` | 其他 | `transferIn` |
| `Redeemed(me, ...)` | — | `redeem` |

### 3.4 组件 Props 约定

```jsx
<BalanceCard   account={addr} token={token} />
<TransferForm  account={addr} token={token} onDone={refresh} />
<StoreList     account={addr} token={token} store={store} onDone={refresh} />
<HistoryList   account={addr} token={token} store={store} refreshKey={n} />
```

- `onDone`：交易成功后由组件调用，父组件 `App.jsx` 用它触发全局刷新
- `refreshKey`：父组件递增的数字，`HistoryList` 用它作为 `useEffect` 依赖重新拉取
- **组件内部不直接修改全局状态**，只通过 `onDone` 通知父级

### 3.5 错误提示对照

| 合约错误 | 用户可读提示 |
|---|---|
| `NotIssuer` | 当前账户没有发行权限 |
| `NotRedemptionStore` | 只有兑换合约可以扣减积分 |
| `InsufficientPoints` | 积分不足，还差 X 分 |
| `OutOfStock` | 该商品已售罄 |
| `ProductNotActive` | 商品已下架 |
| `ERC20InsufficientAllowance` | 请先授权后再兑换 |

## 五、Git 协作规范

### 分支

```bash
main                        # 只接受组长的合并，永远可运行
feat/contract-test          # B
feat/frontend-balance       # C
feat/frontend-store         # D
docs/report                 # E
```

### 提交信息

```
feat: 新增余额卡片组件
fix: 修复 decimals 精度导致的余额错误
test: 补充兑换权限用例
docs: 完成第 2 章架构图
```

### 铁律

1. **组员只推自己的分支，永远不直接推 main**（避免互相覆盖）
2. 每天至少推一次（`git push -u origin feat/xxx`）
3. 绝不提交：`node_modules/`、`artifacts/`、`cache/`、`deployments.json`、`.env`、私钥
4. 合并由 A 操作：
   ```bash
   git checkout main
   git merge feat/xxx
   git push origin main
   ```
5. 拉取前先 `git stash` 或先提交，避免本地改动丢失
